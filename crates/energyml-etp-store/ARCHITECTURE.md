# Bridge (`energyml-etp-store`) - architecture

Related decisions: [ADR 0006](../../docs/adr/0006-bridge-to-the-storage-trait.md) (the bridge itself), [ADR 0001](../../docs/adr/0001-client-architecture.md), [ADR 0002](../../docs/adr/0002-decisions-by-tier.md), [ADR 0003](../../docs/adr/0003-session-and-resumption.md).

## Purpose and position

`EtpStore: EnergymlStorage`: an ETP dataspace behind the storage trait of `energyml-storage`, so that whatever reads a file reads a server without a line changing. It is the acceptance criterion of the client: a viewer or a geometry reader written for files must run unchanged over a server. This is the only crate that names both the EnergyML storage layer and the ETP client. It keeps its name when the other crates become `retp-*`.

## Rules

- **One trait method, one client exchange**: `resources` and `headers` by Discovery (a header's title is the resource name; no object is read), `get_objects` by Store then the registry, arrays by DataArray (metadata first, then whole or by sub-arrays).
- **Locating an object's arrays is not ETP.** `energyml_storage::array::locate_with` does it; the bridge only translates an `ArrayLocation` into a `DataArrayIdentifier`. `file` becomes the **URI** of whatever carries the array: the proxy (`EpcExternalPartReference`) for HDF5 datasets and external dataset parts, resolved from the dataspace listing; **the object itself** for an external data array part, whose file name means nothing to a server. `StartIndex`/`Count` become a region read by `GetDataSubarrays`.
- **An object is read the way its URI names it**; if that type does not exist (some servers write a version-qualified or differently cased type name), the way its root element says, and that is reported as a `Diagnostic`.
- **A failure is said, never an empty answer.** A wholly refused request is `Error::Remote`, an absent object its own `Error::NotFound`, a truncated list a diagnostic. `dataspaces()` without protocol 24 is an error, not `[]`.
- **The client is blocking, the trait async**: each method locks the session for the length of its exchange. A browser supplies its own transport.
- **A dataspace packs into an EPC** (`pack.rs`), written **once for any `Caller`** (the blocking CLI and an async page produce the same package). Three rules: resolution runs over the **whole** dataspace (an `EpcExternalPartReference` no filter names carries the arrays); **a proxy on which an array depends always enters the package**; and **arrays are not written here**, since neither this crate nor a browser writes HDF5. They come back beside the archive and the caller places them.
- **An object changed on the store since it was taken is not overwritten.** `Options::expected` is what the caller knew of each object's `storeLastWrite` when it took it; before writing anything, `push` asks the store what it wrote since the oldest of those times in **one listing** (Discovery with `storeLastWriteFilter` at `since − 1`, because the filter is strict, §3.12.8) and what it deleted (`GetDeletedResources`; absent over REST, which is refused by name, so a deletion goes unnoticed there, as the documentation of `conflicts_of` says). An object written after its capture, or deleted, is a `Conflict`; the push stops before the first island, nothing is written, and the report names them. `Options::overwrite` writes over them and still names them: the reader decides, never the code. A write *at* the time of capture is the one the capture saw, not a conflict.
- **A store is pushed in islands of transactions** (`push.rs`), the inverse of `pack.rs`: any `EnergymlStorage` (a file, another dataspace, another server) into a dataspace, through any `Caller`. Over-splitting is the defence against a server that drops the connection without warning: a cut costs one island, not the model. Two rules, and the first wins: **targets before sources** (an object leaves after everything it references; a cycle stays in one island), then **objects with no array first** as far as the first rule allows (Kahn's algorithm over the condensation of Tarjan's components, with a preference); the island is cut when the kind changes. A budget (objects, bytes) cuts the rest; defaults are to be measured on a server that hangs up, not assumed.
- **An object and its arrays are never separated**: the arrays hang off the object and are written in its island, after its XML and **before** the commit; a store refuses to commit an object whose arrays it does not hold. A test pins it with the fake store's journal: `start, commit, start, array, commit`.
- **What leaves the source is named** (`Report::dangling`) and a refused commit points at it. A reference to an object the source does not hold (most often a well-known `PropertyKind`) is not the push's to invent; but a store that checks references at commit refuses for it with only "reference missing", so the report says where to look.
- **Well-known property kinds are pushed on request, never by default** (`Options::well_known`, `WellKnown::Push(registry)`): among what leaves the source, the `eml23.PropertyKind`s the dictionary knows go as additional objects **with their ancestry**, each written as the dictionary writes it and then **read back by the registry**, so what leaves is an object the reader accepted. A kind no dictionary knows is not invented; it stays a reference that leaves, named in `left_out`. RESQML 2.0.1 names a kind by a word and has no object to push.
- **A refused island stops the push there**, and the report says what left, what failed and why, and what remains: continuing would send islands whose references point at the one that failed. Replay belongs to the runner of the client: an island is redone **whole**, the dead session having cancelled it. What cannot leave at all (an unreadable object, an array whose proxy is missing) is **named** in `left_out`, never omitted: a push that sends less looks like a smaller model.
- **Arrays are read when the island leaves**, not before: the plan asks only for metadata (an array's values *are* the model). An array leaves under the transport §13.2.2.1 permits its logical type (`to_wire`), widths without their own box widened (a `u64` bit for bit, which `values_of` undoes).

## Tests

`tests/etp_bridge.rs` reads and `tests/push.rs` pushes, against a real server `Connection` with handlers serving a small RESQML 2.0.1 model through `MemoryTransport` (`tests/common/mod.rs`); the push test goes to a second fake server that retains what it is written: server-to-server transfer. The last test, `what_reads_a_file_reads_the_server`, asks the question as a viewer would: prefetch, then geometry, code written for files. Three sabotages back the conflict rule (a conflict that does not stop, a deletion that is not one, `>=` instead of `>`). `cargo test --workspace --test etp_bridge --test push`.
